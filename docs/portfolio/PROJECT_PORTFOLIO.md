## 2. Portfolio principles

- Each project has its own POC, scope, backlog, architecture, repository, and acceptance.
- Shared organization policies apply, but project-specific implementation decisions remain with project owners.
- Dependencies must have a provider, consumer, contract, owner, readiness, and fallback.
- Cross-project status is summarized here; source evidence remains in the project repository.
- Do not equate documentation completion with software completion.

## 4. Portfolio-level work

- Reconcile project POCs and scopes with the approved master baseline.
- Confirm project/product boundaries and named owners.
- Normalize detailed epics, sub-epics, user stories, acceptance criteria, dependencies, and evidence.
- Establish a common status reporting model and review cadence.
- Verify branch protections and release gates.
- Identify shared services and avoid accidental coupling.
- Prioritize work based on value, risk, dependencies, capacity, and cost.
